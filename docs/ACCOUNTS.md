# アカウントの一本化（メール・連絡先・カレンダー）

**ステータス:** 設計（2026-10-09）。実装は承認後。連絡先ごとの同期先（`feat/contact-sync-targets`）の後に着手する。

## 0. 方針

- **アカウントを 1 つ登録し、その中で「メール・連絡先・カレンダー」のどれを使うかを選ぶ**
  （Mac の「インターネットアカウント」、iPhone の「アカウント」と同じ考え方。利用者の提案 2026-10-09）。
- 設定の「アカウント」と「同期」を 1 つにまとめる。同じ Gmail が 2 か所に出る状態をなくす。
- **iCloud の連絡先・カレンダー（CardDAV / CalDAV）は、この形の上に作る。**iCloud メールで使っている
  App 用パスワード 1 枚で、連絡先・カレンダーもそのまま使える。

## 1. 今の形（3 つに分かれている）

| 表 | 中身 | 画面 |
|---|---|---|
| `server_accounts` | メールの接続設定（IMAP/SMTP のサーバー・ログイン名）。複数アドレスで共有できる | アカウント |
| `accounts` | メールアドレスごとの設定（同期範囲・保持・署名…） | アカウント |
| `google_accounts` | Google の OAuth 連携（カレンダー・連絡先の同期フラグ、解除中） | 同期 |

## 2. 新しい形

### 2-1. 画面

設定の「アカウント」1 つに、**サービス提供元ごとのカード**を並べる。

```
アカウント
├─ Google  smt.skmk@gmail.com
│    メール      ●  （App 用パスワード / IMAP）
│    連絡先      ●  （Google でログイン / People API）   ← 同期先のアイコン = このカード
│    カレンダー  ●  （Google でログイン / Calendar API）
│    [今すぐ同期] [解除]
├─ iCloud  sng_design@mac.com
│    メール      ●  （App 用パスワード / IMAP）
│    連絡先      ○  （同じ App 用パスワード / CardDAV）   ← 後続で実装
│    カレンダー  ○  （同じ App 用パスワード / CalDAV）    ← 後続で実装
├─ その他  info@sng-design.com
│    メール      ●  （IMAP）
└─ [＋ アカウントを追加]
```

- カードの見出しは提供元（Google / iCloud / その他）とアドレス。
- サービスごとにスイッチ。オンにするときに必要な認証だけを求める。
  - Google のメール → App 用パスワード（今のまま）。Google の連絡先・カレンダー → Google でログイン（OAuth）。
  - iCloud はメール・連絡先・カレンダーとも同じ App 用パスワード。
- **メールを使わないアカウントも置ける**（連絡先・カレンダーだけの Google アカウントなど）。
- 解除（一時的 / 完全）・解除中・再接続は、今の「同期」の作りをカードの中へ移す。
- 署名・同期範囲・保持などメール固有の設定は、カードの「メール」の詳細に置く（今のアカウント設定を移す）。

### 2-2. 追加の流れ

1. 提供元を選ぶ: **Google / iCloud / その他（IMAP）**。
2. アドレスを入れる。Google・iCloud はサーバー設定を自動で埋める（今の autoconfig）。
3. 使うサービスを選ぶ（既定: メール・連絡先・カレンダーすべて。その他はメールだけ）。
4. 必要な認証をまとめて行う（App 用パスワードの入力 → Google の場合は続けてログイン）。
5. 最初の同期。連絡先は今の「反映」の規則（高確信だけつなぎ、迷ったら重複整理）。

### 2-3. データ

- **「アカウント」の表を 1 つ足し、各サービスの表がそこを指す**（今の 3 表は残す。中身を作り直さない）。
  - `account_profiles`（仮）: `id` / `provider`（google / icloud / imap）/ `email` / `display_name` / `sort_order`
  - `accounts`（メール）・`google_accounts`（OAuth）に `profile_id` を足す。iCloud の CardDAV/CalDAV は後続で同じく `profile_id` を持つ表にする。
  - 既存のデータは、同じメールアドレスの `accounts` と `google_accounts` を 1 つの profile にまとめるマイグレーションで移す。
- **つながり表（`contact_identities`）の `account_id` は今のまま**（`google_accounts.id` を指す）。印に出す名前は profile から引く。

### 2-4. OAuth のクライアント情報

今は設定画面でクライアント ID / シークレットを入れる。アカウントの中に混ぜるとさらに分かりにくいので、
**製品として配る前に、アプリに組み込んで利用者には見せない**（デスクトップアプリでは一般的。開発中は
`.env` か開発用の入力欄を残す）。審査（sensitive scope）とテスト公開の 7 日制限は別途。

## 3. 進め方

1. この文書の承認
2. データ（profile の表と移行）と store 層
3. 設定画面の作り直し（カード・サービスのスイッチ・追加の流れ）。「同期」メニューは廃止
4. 連絡先の印・カレンダーの見出しを profile の名前で出す
5. raytrek で確認 → vaio
6. （後続）iCloud の連絡先・カレンダー（CardDAV / CalDAV）をカードのスイッチとして実装

## 4. 決めていないこと

- 1 つの IMAP サーバー設定を複数アドレスで共有している場合（`server_accounts`）のカードの見せ方
  （サーバーごとに 1 枚か、アドレスごとに 1 枚か）。
- メールの別名（エイリアス）や送信専用アドレスの扱い。
