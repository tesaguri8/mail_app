# アプリパスワードでの接続設定（Gmail ほか）

**ステータス:** 実装済み（Gmail 検証済み） / 本ページはユーザー向けマニュアルの元原稿
**目的:** OAuth を使わず、**アプリパスワード**で Gmail などのメールを Rondine に接続する手順をまとめる。ホームページのマニュアル・ヘルプに転用する。

関連: [ONBOARDING.md](ONBOARDING.md)（アカウント追加フロー） / [POSITIONING.md](POSITIONING.md) §5（認証方針）

---

## 0. アプリパスワードとは（なぜ必要か）

Gmail など主要プロバイダは、セキュリティ上の理由で **通常のログインパスワードでの IMAP/SMTP 接続を廃止**しました。代わりに、メールアプリ専用の **16 桁の使い捨てパスワード（アプリパスワード）** を発行して使います。

- Rondine 側は特別なことをしません。アプリパスワードは **普通のパスワードとしてそのまま**入力すれば接続できます（OAuth・Googleログイン画面は不要）。
- 発行にはアカウントの **2 段階認証（2FA）が有効**であることが前提です。
- 万一漏れても、Google 側で該当のアプリパスワードを削除すれば、その接続だけを無効化できます（本体パスワードは変えなくてよい）。

> 資格情報は OS の金庫（Windows 資格情報マネージャー / macOS キーチェーン / Linux Secret Service）に保存され、平文でディスクに残しません。

## 1. Gmail

### 1-1. 2 段階認証を有効化（未設定の場合）

1. [https://myaccount.google.com/security](https://myaccount.google.com/security) を開く
2. 「Google へのログイン」→ **2 段階認証プロセス** を選び、画面に沿って有効化（電話番号での確認など）

> すでに有効なら次へ。**2 段階認証がオフだと、次の「アプリ パスワード」メニューが表示されません。**

### 1-2. アプリパスワードを発行

1. [https://myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) を開く（この画面へ直接飛べます）
   - 開けないときは、セキュリティ画面の検索窓に「**アプリ パスワード**」と入力しても辿れます
2. 再ログインを求められたら、Google アカウントのパスワードを入力
3. **アプリ名**を入力（任意でOK。例：`Rondine`）→ **作成**
4. **16 桁のパスワード**が表示される（`abcd efgh ijkl mnop` のように 4 文字 × 4 の並び）
5. この 16 文字を控える（**この画面を閉じると二度と表示されません**）

### 1-3. Rondine に入力

1. アカウント追加画面でメールアドレスを入力 →「**自動判定**」
   （`imap.gmail.com:993 (SSL)` / `smtp.gmail.com:587 (STARTTLS)` が自動で入ります）
2. パスワード欄に、発行した 16 文字を入力
   - **スペースは入れず**に続けて入力（`abcdefghijklmnop`）。※スペース込みでも通ることが多いですが、無しが確実です
   - Google の**ログインパスワードではなく、この 16 桁**を使う点に注意
3. 「**接続テスト**」→ 成功したら「**追加**」

### 1-4. つまずきポイント

- **「アプリ パスワード」が見当たらない**：2 段階認証がオフ、または**パスキーのみ**設定の状態だと出ないことがあります。まず電話番号ベースの 2 段階認証を有効化してください。
- **会社・学校の Google Workspace アカウント**：管理者がアプリパスワードを無効化していると発行できません。管理者に依頼するか、将来対応の OAuth（Google ログイン）が必要になります。
- **接続テストが失敗する**：入力した 16 桁にタイプミス・余分な空白がないか、メールアドレス（＝ユーザー名）が正しいかを確認。

### 1-5. 接続後の挙動メモ

- **送信済みメールは二重になりません。** Gmail は SMTP 送信時にサーバー側が自動で「送信済みメール」に控えを保存するため、Rondine 側はあえて控えの追加保存（IMAP APPEND）を行いません。送信した控えは次回同期で 1 通だけ取り込まれます。
- Rondine が同期するのは **受信トレイ＋送信済み／下書き／ゴミ箱／迷惑メール**です。Gmail の「すべてのメール（All Mail）」は同期しないため、全メールが重複することはありません。

## 2. iCloud メール（Apple）

Gmail と同じ **「2 ファクタ認証 →専用パスワード」** 方式です。Apple では名前が違い、**「App 用パスワード（App-Specific Password）」** と呼びます。

### 2-1. 2 ファクタ認証を有効化（未設定の場合）

- App 用パスワードの発行には、Apple ID の **2 ファクタ認証**が必要です（近年はほぼ必須のため、多くの場合すでに有効）。
- 未設定なら [account.apple.com](https://account.apple.com) → **サインインとセキュリティ** から有効化。

### 2-2. App 用パスワードを発行

1. [account.apple.com](https://account.apple.com) にサインイン
2. **サインインとセキュリティ** → **App 用パスワード** を選ぶ
3. ＋（または「App 用パスワードを生成」）→ 名前を付ける（例：`Rondine`）→ 生成
4. **16 文字（英小文字・ハイフン区切り）** が `abcd-efgh-ijkl-mnop` の形で表示される → 控える（**この画面を閉じると再表示できません**）

### 2-3. Rondine に入力

1. メールアドレス（＝Apple ID）を入力 →「**自動判定**」
   （`imap.mail.me.com:993 (SSL)` / `smtp.mail.me.com:587 (STARTTLS)` が自動で入ります）
2. パスワード欄に、発行した文字列を **表示どおり（ハイフン込み）** で入力
   - ※通らなければハイフンを外して再試行
3. 「**接続テスト**」→「**追加**」

### 2-4. 注意点

- **本体（Apple ID）のパスワードを変更・リセットすると、すべての App 用パスワードが自動的に失効**します。その際は再発行して入れ直してください。
- ユーザー名は **Apple ID のメールアドレス全体**。
- Apple ID の 2 ファクタ認証がオフだと発行できません。

## 3. その他のプロバイダ（要・掲載前確認）

以下も **アプリパスワード方式**で接続できます（自動判定に対応済み）。手順の細部は各社UIの変更が入りやすいため、**マニュアル掲載前に最新画面で確認**してください。

| プロバイダ | 自動判定される設定 | 発行の入口 | 備考 |
|---|---|---|---|
| **Outlook / Hotmail / Live** | `outlook.office365.com:993` / `smtp.office365.com:587` | [account.microsoft.com/security](https://account.microsoft.com/security) → 追加のセキュリティ | 2 段階認証の有効化が前提。個人アカウントのみ |
| **Yahoo!メール（.com）** | `imap.mail.yahoo.com:993` / `smtp.mail.yahoo.com:465` | アカウントセキュリティ → アプリパスワードを生成 | — |
| **Yahoo!メール（.co.jp）** | `imap.mail.yahoo.co.jp:993` / `smtp.mail.yahoo.co.jp:465` | — | **IMAP の有効化**が別途必要な場合あり |

> **さくらのメール**などの独自ドメインは、メールボックスのパスワードをそのまま使います（アプリパスワード不要）。ユーザー名はメールアドレス全体。

## 4. カレンダー・連絡先について（補足）

メールとは**別プロトコル**なので、「メールを繋いだら自動でカレンダーも取れる」わけではありません（Rondine のカレンダー／住所録同期は別機能・別実装）。

- メール＝ **IMAP/SMTP** ／ カレンダー＝ **CalDAV** ／ 連絡先＝ **CardDAV**
- **iCloud**：同じ **App 用パスワード 1 枚**で Mail・Calendar(CalDAV)・Contacts(CardDAV) すべてに使える（`caldav.icloud.com` / `contacts.icloud.com`、Basic 認証 over SSL）。カレンダー機能を実装する際は追加発行不要。
- **Google**：**2025-03-14 以降、第三者アプリの Calendar/Contacts(CalDAV/CardDAV) は原則 OAuth 2.0 が必要**（アプリパスワードでのメール接続はそのまま可）。Google カレンダー連携は **OAuth 前提**で計画する。
  - ただし Google カレンダー／連絡先は **sensitive スコープ**であり、**審査は無料**（同意画面レビューのみ。Gmail 本文の restricted スコープと違い、有料の年次 CASA 監査は不要）。テスト状態なら最大 100 ユーザーまで審査なしで動作。費用の壁は低い。
