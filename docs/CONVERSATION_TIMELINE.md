## 1. 見た目と動き

> **`[確定]` 2026-10-11 利用者の要望で改めた**（「バブルの始まり地点に日付があると良い。月と日の表示が
> 全く無いので、あまり意味が無い」）。目盛りを件数に比例する位置から**各バブルが実際に始まる位置**へ移し、
> 各日の始まりに**月日の札を常に出す**ようにした。件数に比例する元の形は、一覧用に部品へ残してある（§3）。

```
│ 2025/12/26 ─   ← 最初の札と、年が変わるところは年も出す（太字）
│            ─   ← 同じ日の 2 通目以降は点だけ
│      12/27 ─   ← 各日の始まりに月日の札。点はどれもそのバブルの上端の位置
│ ──────── 2025年12月30日(火)   ← マウスの位置の日付を大きく出す
│      12/30 ─ ┃ ← 右端の帯: いま見えている範囲（スクロールの割合）
│   2026/1/3 ─ ┃
```

| 項目 | 決め |
|---|---|
| 置き場所 | **バブル表示の左端**（Photosky と同じく左。検索の一致移動バーは右上のまま） |
| 範囲 | 会話に出しているメール全部（ゴミ箱・迷惑を隠しているときは、隠したあとの並び） |
| 目盛りの位置 | **各バブルの上端 ÷ スクロールできる全体の高さ**。線は会話の縮図になる（長いバブルは間が広い） |
| 点 | **全バブルぶん**出す（札を間引いても点は残す） |
| 札 | 各日の始まりに**月日（10/2）を常に出す**。最初と年が変わるところは**年も**（2026/1/3・太字）。同じ日が続くときは最初の 1 つだけ。詰まって重なるときは 年の変わり目 → 月の変わり目 → 上のほう の順に残す（間隔 13px） |
| 押す・引っ張る | 押した位置の割合へスクロールする（点を押せばそのバブルが上端に来る）。点から 6px 以内は点に吸い付ける（札は点を中心に置くので、札の上半分を押しても前の日にならないように）。引っ張っている間は日付を出し続ける |
| いま見ている位置 | 右端の帯 ＝ 見えている範囲（scrollTop 〜 scrollTop + 表示域の高さ）÷ 全体の高さ。スクロールバーのつまみと同じ |
| 近づけたとき | マウスの位置の日付と、その日を含む年・月の帯を出す。**魚眼の拡大は外した**（§2.1） |
| 出さないとき | **会話が画面に収まる（スクロールできない）とき**。日時の分かるメールが 1 通も無いとき |

## 2. 仕組み

Photosky は写真が何万枚にもなるので、日ごとの件数を DB で数え、飛んだ先だけを読む。
会話は **threadView で全メールを読み込み済み**（多くて数十通）なので、DB もコマンドも足さず、手元で済ませる。

| 段 | 何をするか | どこ |
|---|---|---|
| ① 日ごとの件数 | 会話の**並び順のまま**、同じ日が続くところを 1 つに数える（端末ローカルの日付） | `timeline/dayCounts.ts` の `countByLocalDay` |
| ② 始まりの位置 | 各バブル（と未受信の引用の枠。§2.3）の上端を DOM から測り、スクロールできる全体の高さ（`scrollHeight`）に対する割合にする | `timeline/marks.ts` の `readMarks` → `startFractions`（`Conversation` の `measureTimeline`） |
| ③ 線の配置 | 区間の上端 ＝ その日の最初のバブルの始まり、下端 ＝ 次の区間の上端。札を選ぶ | `scrubberLayout.ts` の `layoutSegmentsAt` / `buildDayLabels` |
| ④ 飛ぶ | 押した位置の割合 × 全体の高さ − 余白 12px へスクロール（0 〜 最大で頭打ち） | `scrollTopForFraction` → `Conversation` の `jumpToFraction` |
| ⑤ いまの位置 | スクロールのたびに見えている範囲の割合を出し、帯にする | `Conversation` の `measureTimeline`（`viewRange`） |

- **何通目とバブルの番号を必ず揃える**:
  - 日時の無い・読めないメールも**件数から落とさない**（直前のメールの日に数える。先頭なら最初に日の分かるメールの日）
  - 並びが日付の順から外れていても（時計のずれたメールなど）並べ替えない。**同じ日でも続いていなければ別の区間**にする
    （目盛りは同じ日付がもう一度出ることがある。区間の順序 ＝ バブルの順序を優先した）
- **測り直す契機**: スクロール・枠の大きさの変化・各バブルの高さの変化（本文の到着・全文の開閉・画像の読み込み）。
  `ResizeObserver` で拾い、描画 1 回につき 1 回だけ測る
- **スクロールできるか**も同じ契機で測る（`scrollHeight > clientHeight`）
- 位置が変わらなければ同じ配列のまま渡す（スクロールのたびに区間・札を組み直さない）

#### 部品の外から見える形（props）

`TimelineScrubber` は**目盛りの位置の決め方を外から渡せる**。会話と一覧（wt-2）で同じ部品を使う。

| props | 会話（位置に合わせる） | 一覧（件数に比例・元の形） |
|---|---|---|
| `days` | 渡す | 渡す |
| `starts?` | 各件の始まりの割合（0〜1・昇順）を渡す → 札・点を出し、魚眼は切る | 渡さない → 件数に比例・魚眼で目盛りが細かくなる |
| `accents?` | 各件が未受信の引用の枠か（`starts` と同じ並び）→ その件の点と、その件で始まる日の札を控えめに出す | 渡さない |
| `badges?` | 各件に添付・リンクがあるか（`starts` と同じ並び）→ 左端にクリップ・鎖を出す（§2.4） | 渡さない |
| `viewRange?` | 見えている範囲の割合 → 帯を出す | 渡さない |
| `viewOffset?` | 渡さない | 一番上の件の番号 → 印を出す |
| `onJump(offset, fraction)` | `fraction`（押した位置の割合）でスクロール | `offset`（何件目）で飛ぶ |

### 2.3 未受信の引用の枠も載せる（2026-10-14）

> **`[確定]` 2026-10-14 利用者の要望**（「バブルが細かくなったのに、タイムラインに日付が表示されないのでもったいない」）。
> 転送の中の 1 通ずつが枠（`UnseenQuotes`。[THREADING.md](THREADING.md) §5）に分かれるようになったので、
> 枠も 1 件ずつ目盛り・札にする。

- **数え方**: バブルの包み（`id="bubble-…"`）と各枠に**目印の属性**（`data-timeline-date`＝日時。枠には
  `data-timeline-quote` も）を付け、`readMarks` が DOM の並び順に読む。並びは「枠（古い順）→ その親のバブル → 次の枠 → 次のバブル」（2026-10-20 から。目印はバブル本体に付ける）。
  **日ごとの件数（`days`）と位置（`starts`）を同じ目印の並びから作る**ので、件数がずれない
  （`summarizeMarks`）。枠は「引用を表示」「全文を開く」の間は消えるので、データからではなく**描かれているもの**から数える
- **枠の日時**: Rust が見出しの日時を `quotes::when::parse_quoted_time` で読み、ISO 8601 にして渡す
  （`UnseenQuote.date`・`QuotedTime::to_iso`）。日時の解析を TS で書き直さない。
  - 時差が書かれていれば `2026-10-09T15:29:01+09:00`（端末の時刻に直して日を決める。バブルの `date` と同じ）
  - **時差の無い日時**（Outlook の `Sent:`・日本語の `送信日時:`）は時差を付けない `2026-10-07T19:36:00` にし、
    端末の時刻として読む。照合（`store/quote_match.rs`）が「書かれていたままの時刻」どうしで比べるのに合わせた。
    **見出しに書かれた日付と札の日付がそろう**（送り手と端末の時差で日がずれることはある。時差が分からないので割り切る）
  - 日時の読めない引用はもともと枠にしない（差出人と日時の両方が要る）ので、`date` は必ずある。
    バブル側の日時の無いメールは、これまでどおり直前の件の日に数える
- **日付が逆に進む**（**2026-10-20 に解消**: 枠を古い順にして親のバブルの上に置いた。[THREADING.md](THREADING.md) §5。
  並びは「枠（古い順）→ その親のバブル → 次の枠 → 次のバブル」になり、つまみは上から下へ単調に進む。
  `UnseenQuotes.test.tsx` で固定。下の確かめは、日付の戻る並びでも崩れないことの記録として残す）:
  以前は、枠は転送の中の新しい順（10/9 → 10/7 → … → 10/2）に並んでいた。区間・札は**並び（位置）の順**で
  作り、日付の順に並べ替えない（§2 の「並べ替えない」と同じ）。確かめたこと（`scrubberLayout.test.ts`）:
  - `layoutSegmentsAt` は位置の昇順だけを使うので崩れない。`topVisibleIndex`・`viewRange` も位置だけを見る
  - `buildDayLabels` の年は「前の区間と年が違えば付ける」ので、年が戻るところ（2026/1/5 → 2025/12/26）にも付く
  - **直した**: `parentBands`（マウス位置の年・月の帯）が、同じ月の区間を並び全体から集めていたため、
    離れた同じ月（10/12 → 9/30 → 10/13）をつないでしまっていた。マウスの区間から**続くところまで**に改めた
    （日付が順に並ぶ一覧では結果は変わらない）
- **見分け**: 枠から来た件の点は短く薄く（`w-1`・白 25%）、その件で始まる日の札は薄く（白 35%）する。
  枠そのものが「地の色はバブルと同じ・枠線だけ点線」で控えめなので、つまみでも主役のバブルより一段下げた
  （琥珀色にする案は、枠の琥珀色をやめたのに合わせて取りやめた）
- 札を押すと、その枠が上端に来る（位置は枠の上端なので、§2 の ④ のままでよい）。最大スクロール量で頭打ちになる
  下のほうの枠は、それ以上は上がらない

### 2.4 添付・リンクの目安のアイコン（2026-10-20）

> **`[確定]` 2026-10-20 利用者の要望**（「リンクや添付があるメールはアイコンを付けたい。目安として分かれば助かる。
> 発火はしなくてよい」）。

- **何に付けるか**: 目印の属性に `data-timeline-attach`（添付あり）・`data-timeline-link`（リンクあり）を足し、
  `readMarks` が読む。付け方はバブルと枠で `markAttrs` の 1 か所にそろえた
  - **添付**: バブルの `has_attachments`。**枠には付けない**（添付は外側のメールのもので、どの枠のものか分からない。
    [THREADING.md](THREADING.md) §5）
  - **リンク**: 本文に http(s) / www. の URL がある。**判定は表示と同じ**（`HtmlText.tsx` の `hasAutoLinkUrl`。
    `AUTOLINK_RE` を共有し、別の正規表現を作らない）。**メールアドレスだけ（署名の `<mailto:…>`）は数えない**
    （どのメールにも付いてしまう）。バブルはバブルが既定で出す本文（`clean_body`、無ければ `body_plain`）で、
    枠は枠の本文で数える。**HTML だけのメール（プレーン本文が無い）は数えない**（割り切り）
- **出し方**: 線の左端の列（`left-1`）に 9px のアイコン。両方あれば並べる。色は札の文字と同じ薄さ（白 60%。
  枠だけをまとめたものは枠の札と同じ白 35%）。**押しても何も起きない**（`pointer-events-none`・`aria-hidden`。
  押した位置はそのまま線が受け、いままでどおりその件へ飛ぶ）。ツールチップは付けない。
  列を取るため、つまみの幅を 88px（`w-22`）→ 104px（`w-26`）にした（年付きの札「2026/10/20」と重ならないように）
- **詰まったところ**: 札（`buildDayLabels`）と同じ最小の間隔（13px）より近いアイコンは、**手前の件に 1 つにまとめる**
  （`buildBadges`。まとめた件のどれかにあれば出す）。**隠さない**のは、目安が消えると「無い」と読めてしまうため。
  点（目盛り）は間引かず全件出すので、まとめたアイコンはその並びのいちばん上の点の高さに出る

### 2.1 Photosky から落としたもの

- **撮影日不明**の区間・目盛り・ラベル（メールにはその行が無い。日時の無いメールは上のとおり直前の日に数える）
- 行の組み立て・範囲読み（`gridWindow.ts` の `buildGridRows` / `rowIndexOfOffset` / `offsetRangeOfRows` / `pagesForRange`）。
  写したのは `DayCount` の型だけ
- 色は Rondine の配色（白の濃淡＋sky）に置き換えた（Photosky の `theme-*` は Rondine に無い）
- **会話では魚眼の拡大を外した**（一覧用の件数比例では残す）。理由:
  - 札が常に出ているので、近づけて細かくする役目が無い（詰まって間引かれた札の日付は、マウスの位置の日付で分かる）
  - 引き伸ばすと点がバブルの本当の位置からずれ、「点 ＝ バブルの始まり」が崩れる
  - マウスを動かすたびに札が動くと、どこを押せばよいか目で追いにくい

### 2.2 割り切り・既知の課題

- つまみが出ると表示域が少し狭くなり、バブルが折り返して伸びる。**ちょうど収まるかどうかの境目**では、
  出す → 伸びてスクロールできる、のように落ち着く方へ寄るが、逆向き（出す → 収まる → 消す → はみ出す）の
  行き来が理屈の上では起こりうる。実際に見えたら、出す条件に余裕（数十 px）を持たせる
- 全文を開いたバブル（高さ上限 70vh・内部スクロール）も 1 通として数える。全文の中の位置は帯に出ない
- 線は会話の縮図なので、**短いバブルが続くところは点と札が詰まる**（札は間引き、点は重なる）。
  時刻の近さではなく、画面の上の近さで詰まる

## 3. 次の段: メール一覧にも付けるとき

> **`[済]` 2026-10-11**: メール一覧にも付けた。作りと割り切りは [MAIL_LIST_TIMELINE.md](MAIL_LIST_TIMELINE.md)。
> 下の表は着手前の見立て（一覧は仮想化していなかった・行の高さは固定せず測ることにした、など実装で変わった点がある）。

一覧は会話と違い、**数千〜数万通を全部は読み込まない**。Photosky と同じ作り直しが要る。

| 段 | 何が要るか | 今の会話との違い |
|---|---|---|
| 日ごとの件数を DB で数える | **一覧と同じ絞り込み・並び順**で `GROUP BY` した日ごとの件数を 1 本の問い合わせで返すコマンド。日付キーは**並びの式そのものの先頭**から取り、同じ日の行が一覧で必ず連続し、**累計が `OFFSET` と一致する**ようにする（Photosky `count_by_local_day` / 試験 `day_offsets_match_find_all_paging`） | 会話は手元で数える |
| 端末のタイムゾーン | 一覧の日付の区切りは端末ローカル。DB の日時は UTC なので、数えるときにローカルへ寄せる方法を決める（SQLite の `'localtime'` は Rust 側の TZ に依存する） | 会話はフロントで `Date` に任せている |
| 同じ時刻の並びを固定する | 並びに一意な列（`id`）を足す。`OFFSET` で途中から読むとき、ページの境目で行が入れ替わって重複・欠落しないように | 会話は全部読むので不要 |
| 仮想化 | 一覧は既に仮想化している（`useVirtualRows`）。**全期間ぶんの行を先に組み**、読み込んでいない位置は高さだけのプレースホルダにする | 会話は全バブルを DOM に置く |
| `OFFSET` での範囲読み | 上から順に読み足すのをやめ、**スクロールが止まった場所の前後だけ**をページ単位で読む（Photosky の `onRequestRange` / `pagesForRange`）。飛ぶ途中は読まない | 会話は不要 |
| 行の高さ | 全体の高さを最初から決めるため、**行の高さを固定**する（またはスレッドの行・日付の見出しの高さを型で決める）。会話のバブルは高さがまちまちなので、DOM を測っている | 会話は測る |
| 画面側の絞り込み | 一覧には**フロントだけでかけている絞り込み**（タグ・VIP・グリーンなど、`mailFilters.ts`）がある。DB の件数と画面の行がずれるので、**絞り込みを DB 側へ寄せる**か、絞り込み中はつまみを手元の行から作る（Photosky も「全件を手元に持つ表示」は手元で数える） | 会話には絞り込みが無い |
| スレッド単位の一覧 | 一覧はスレッドを 1 行にまとめる。**どの日付で数えるか**（代表メールの日時）を、並びの式と同じにする | — |

このとき、`timeline/` の部品（`TimelineScrubber` と `scrubberLayout`）は**そのまま使える**ように作ってある
（`days` / `viewOffset` / `onJump` の 3 つだけを受け取る）。作り直すのは件数の出し方と、一覧側の offset ↔ 行の対応。
