# グリーンドメイン（安全と認めた差出人ドメイン）

「スパム（危険を弾く）」とは別軸の、**ユーザーが“見たい相手”を積極的に肯定リスト化する**キュレーション機能。
勝手に届くメールが多い中で、「この差出人は自分が認めたドメインだ」と分かるとメールが格段に見やすくなる。

アイコンは `leafy-green`（若葉）。メール一覧・詳細に**グリーンバッジ**を出し、**「グリーンのみ」フィルタ**で絞り込める。
関連: [SPAM.md](SPAM.md)（迷惑メール）／[FILTERING.md](FILTERING.md)（絞り込み全般）。

## 判定ルール（is_green）

差出人アドレスが次のいずれかならグリーン。

1. **本人**: 差出人が住所録に登録済み（アドレス完全一致＝`is_known` 相当。削除済み連絡先は除く）。
2. **ドメイン**: 差出人ドメインが「グリーン集合」に含まれる。

```
グリーン集合 =（手動認定 green_domains ∪ 住所録由来ドメイン）− フリーメール − 警告 warning_domains
```

- **住所録由来（自動グリーン）**: 住所録の連絡先メールのドメインを自動でグリーン扱い（会社ドメイン等）。
- **フリーメール除外**: `gmail.com` などのフリーメールは、1 人を認めただけでドメイン全体（＝誰でも取得できる無関係な差出人）が許可されてしまうため、**自動・手動を問わずドメイン単位ではグリーンにしない**（本人＝`is_known` だけグリーン）。一覧は `services/store/greendomain.rs` の `FREEMAIL_DOMAINS`。
- **手動認定（green_domains）**: メール詳細やグリーンドメインタブから任意のドメインを認定できる。ただし**フリーメールは拒否**（`add_green_domain` が `false` を返し、UI は「住所録に登録して本人を信頼する」よう案内）。旧バージョンで登録済みのフリーメール行は起動時に掃除する（`purge_freemail_green_domains`）。
- **警告（warning_domains）**: グリーンから**意図的に外した**ドメイン。住所録由来の自動グリーンを**上書き除外**し、連絡先がいても再登録されないようにする（＝再グリーン化を防ぐ）。本人一致（`is_known`）は残る。

## データモデル

- `green_domains(domain PK, note, created_at)` … 手動認定。
- `warning_domains(domain PK, note, created_at)` … 意図的な除外（グリーン解除）。
- 判定・管理は `services/store/greendomain.rs`。マイグレーション `0028_green_domains.sql`。

状態遷移（ドメイン単位）:

- **認定** `green_domain_add`: warning から外し green へ（戻り値 `bool`。フリーメールは認定せず `false`）。
- **解除** `green_domain_warn`: green から外し warning へ（自動再グリーンを防ぐ）。
- **中立に戻す** `green_domain_clear`: green・warning の両方から外す（住所録由来なら自動グリーンに戻る）。

`MailSummary.is_green` / `MailDetail.is_green` は取得時に算出（グリーン集合を 1 回だけ引いて全行に付与）。
個別アドレスの判定は `green_address_check(address)`（`bool` を返す）。一覧・詳細の付与とは別に、任意アドレスを単発で照会するのに使う。

## UI

- **メール一覧・詳細**: グリーンバッジ（`leafy-green`）。詳細に「このドメインをグリーンに認定／解除」ボタン。
- **フィルタ**: 一覧ツールバーに「グリーンのみ」トグル（`is_known`/`is_vip` と同じ仕組み）。
- **住所録＞グリーンドメインタブ**: グリーン（手動＋住所録由来を区別）／警告の一覧・追加・解除・中立化。

### フリーメールの差出人を「この人だけ」グリーンにする（`FreemailGreenPrompt`）

メール詳細の葉っぱ・会話のバブルの右クリック「グリーンに認定」で、差出人がフリーメール（`green_domain_add` が
`false`）なら、**その場で確認を出す**: 「gmail.com はドメインごとには認められません。〈名前〉さん（アドレス）を
住所録に登録して、この人だけグリーンにしますか？ ［登録する］［やめる］」。

- **作る前に照合する**: `contact_lookup_email(email, include_deleted: true)`（ゴミ箱を含む小文字の完全一致）。
  - 無い → 差出人の表示名（無ければアドレス）とアドレスで作る
  - 削除されていない連絡先がある → 作らない（既にあることを伝える）
  - ゴミ箱にだけある → 作らず、「戻す」かを訊く（`contact_restore`。戻せばグリーン）
- **書き込みは住所録の普段の作成と同じ経路**（`utils/senderContact.ts`）: `contact_upsert` ＋ 新規作成の既定の
  同期先（`defaultTargets`＝連携中で連絡先を同期している Google アカウント。前回外したものは外したまま）へ
  `contact_sync_target_add`（作成待ち。次の同期で Google に作る）。新しい書き込み口は無い。
- 作れたら、その場で葉っぱ・バッジをグリーンにし、`onGreenChange` で一覧を読み直す（グリーンの絞り込みにも出る）。
- 文言は折り返して全部出す（道具の行に詰めない。狭い窓で「「gm…」と切れて読めなかった / vaio・alpha.67）。

### 住所録の本人の葉っぱを外そうとしたとき（`useSenderGreen`）

グリーンは「ドメインがグリーン」か「住所録の本人」のどちらか。葉っぱはドメインの認定を付け外しするので、
**住所録の本人は葉っぱでは外せない**（住所録を勝手に消したり書き換えたりしない）。以前は外した見た目に
一瞬変わり、読み直すとグリーンに戻っていた。いまは外す前に住所録を引き直し（`contact_lookup_email`）、
結果どおりにだけ見た目を変える:

| 本人か | ドメイン | すること | 見た目 |
|---|---|---|---|
| いいえ | （グリーン） | ドメインを警告に回す（`green_domain_warn`） | 外れる |
| はい | グリーン（手動 or 住所録由来） | ドメインだけ警告に回す | グリーンのまま。「ドメインの認定は外したが、本人は住所録にいるのでグリーンのまま」と出す |
| はい | グリーンでない（フリーメール等） | 何も書かない | グリーンのまま。「住所録に登録されているためグリーン。外すには住所録から外す」と出す |

お知らせには［住所録で開く］を付ける（差出人名に関連する連絡先を優先）。メール詳細と会話のバブルで同じ
フックを使う（`components/SenderGreen.tsx`）。

**住所録にあるのにグリーンにならない場合**（本人一致は `contact_exists_sql`: 削除されていない連絡先の
`lower(value) = lower(差出人)`）:

- 連絡先がゴミ箱にある（上の「戻す」で解消）
- アドレスの大文字小文字が ASCII 以外で違う（SQLite の `lower` は ASCII だけ。実用上はまず起きない）
- 前後の空白は、保存時（`required` の trim）と照合時（差出人の trim）の両方で落とすので影響しない
- 表示の取り残し: 会話のバブルの印は読み込んだ時点の値。全文表示で変えたときはバブルにも伝える
  （`MailBody` の `onGreenChange(green)`）

## スパム機能との連携（将来・未実装）

グリーンは「見やすさのための肯定リスト」、スパムは「危険/迷惑の否定判定」。両者は補完的で、次の連携が有効（[SPAM.md](SPAM.md)）。

1. **グリーンは自動隔離しない（ホワイトリスト保護）**: `is_green` の差出人は迷惑スコアが高くても自動隔離（quarantine）せず、受信トレイに残す。誤隔離を防ぐ安全弁。実装案: `services/spam/apply.rs` の隔離判定に「green ならスキップ」を追加。
   ただし**ユーザーがそのアドレスを名指しで迷惑登録している場合は除く**（アドレス単位の指定がドメイン単位の信頼に勝つ。[SPAM.md](SPAM.md) §8.5 の優先順位）。
2. **警告ドメインは弱いスパム寄与**: `warning_domains` の差出人に軽いスコア加点、または「迷惑かも」表示のヒントに使う（隔離まではしない）。
3. **迷惑マークからの示唆**: あるドメインを繰り返し迷惑マークしたら、そのドメインを警告候補として提案（グリーン解除の導線）。
4. **表示の整合**: グリーンバッジと「迷惑かも」警告が同時に立つケースはグリーンを優先表示（ユーザーが認めた相手を尊重）。

実装時は本ドキュメントの状態遷移・除外規則（フリーメール／警告の上書き）を壊さないこと。
