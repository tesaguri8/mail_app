# メール一覧の日付のつまみ（タイムライン・スクラバー）

> **`[確定]` 2026-10-11 利用者の了承**: メール一覧（サイドバー・`MailboxView.tsx`）の**左端**に、
> 会話と同じ日付のつまみを付ける。作りは Photosky の `docs/design/TIMELINE_SCRUBBER.md` §2
> 「読み込んでいない日付へ飛ぶ仕組み」と同じ（**DB から先に全体の件数と日付の位置を出し、飛んだ先の前後だけを読む**）。
> 部品（`components/timeline/`）は会話と共有する。会話側の設計は [CONVERSATION_TIMELINE.md](CONVERSATION_TIMELINE.md)。

## 1. 見た目と動き

| 項目 | 決め |
|---|---|
| 置き場所 | **一覧の左端**（幅 64px。会話と同じ部品・同じ見た目） |
| 範囲 | いまのアカウント（「全て」なら全アカウント）・フォルダの、全スレッド |
| 長さ | **スレッド数に比例**（件数に比例する元の形。魚眼で近くだけ細かく） |
| 押す・引っ張る | その日（日の途中ならそのスレッド）の行を一番上へ。読み込んでいなければ、止まったところで読む |
| いま見ている位置 | 線の上に印（一番上に見えている行） |
| 出さないとき | **画面側の絞り込み中**（トグル・期間・タグ）・**検索中**・一覧が画面に収まるとき・日時の分かるスレッドが無いとき |

- 以前の右端の「スクロール中だけ出る年月の札」は、つまみに統合して消した

## 2. 仕組み

| 段 | 何をするか | どこ |
|---|---|---|
| ① 日ごとの件数 | `thread_list` と**同じ絞り込み・並び**で、代表メールの日付（端末ローカル）ごとにスレッドを数える。1 本の `GROUP BY` | コマンド `thread_day_counts` → `store/thread_days.rs` |
| ② 全期間ぶんの枠 | 件数の合計だけ枠（`slots`）を作る。読み込んだ位置だけ行が入り、残りは**高さだけのプレースホルダ** | `mailListWindow.ts`（`emptySlots` / `fillSlots`） |
| ③ 仮想化 | `@tanstack/react-virtual`（Photosky と同じ 3.13 系）。**行の高さは描いてから測る**（`measureElement`）。見積もりは 92px | `MailboxView.tsx` の `rowVirtualizer` |
| ④ 飛ぶ | つまみの offset ＝ 枠の番号。`scrollToIndex(offset, { align: 'start' })` | `jumpToOffset` |
| ⑤ 飛んだ先だけ読む | スクロールが止まったら（80ms）、見えている行の前後 1 画面分を **100 件単位のページ**に分け、未読み込みの位置を含むページだけ `OFFSET` で読む。引っ張っている間は読まない | `pagesToLoad` → `requestRange` |

- **累計を OFFSET と一致させる決め**:
  - 日付キーは**並びの式（`date_ts DESC, id DESC`）の先頭**を日付にしたもの（`date(date_ts, 'unixepoch', 'localtime')`）。
    同じ日のスレッドは一覧の中で必ず連続し、累計がそのまま `OFFSET` になる（Rust の試験 `day_offsets_match_list_paging`。
    UTC・New York・Kolkata の時間帯でも通ることを確かめた）
  - 同じ時刻のスレッドは `id DESC` で順序が決まっている（以前から）。ページの境目で入れ替わらない
  - **日時の無いスレッドは最後**（`date_ts` が NULL。SQLite の DESC で最後に来る）。つまみでは直前の日に数える（`toDayCounts`）
  - ローカル日付は SQLite の `'localtime'`（Rust のプロセスの時間帯＝WebView と同じ機械の設定）
- **一覧の更新との整合**:
  - 削除・移動で一覧から外した行は、**枠から抜いて詰め**、日ごとの件数も減らす（`updateLoaded` / `dropFromDays`）。
    DB からも消えるので、後ろの offset もそのまま揃う
  - 読む間に並びが動いて、同じスレッドが別の位置に残っていたら、古い位置は未読み込みに戻す（二重に出さない）
  - 読み直し（同期・操作のあと）は、日ごとの件数と**見えている範囲**を読んでから枠を差し替える（空白を挟まない）。
    位置はそのまま。新着が先頭に入ると、従来どおり中身が下へずれる
  - フォルダ・アカウントの切り替えだけは先頭の 1 ページを読み、先頭に戻す
- **読み込んである行だけが対象の操作**（従来と同じ考え）: 矢印キーの移動・Shift の範囲選択・会話の解決は、読み込んである行の並びで行う。
  まだ読んでいない位置を飛び越えて範囲選択はしない。**全件選択**（ヘッダのチェック）は従来どおり DB から全代表を引き直す
- 使われなくなった `thread_count`（コマンド・TS）と、`mailbox.loadingMore` の文言を消した

### 2.1 行の高さ（`[実測]` 2026-10-11 raytrek）

一覧の見た目は変えていない。行の高さは**本文の行数（0〜2 行）**・選択中のチェックボックスによる折り返しで揃わないので、
描いてから測っている。

- **飛ぶ先はずれない**: つまみが扱うのは「何件目か」だけで、px ではない。`scrollToIndex` はその行の位置を
  （まだ測っていない行は見積もりで）計算して寄せ、行が描かれて実際の高さが分かると、もう一度寄せ直す。
  上の行の高さが見積もりと違っても、表示域より上の行の変化はスクロール量の補正で吸収される（tanstack の既定動作）
- GUI で 5 か所に飛んで、**一番上の行の日付がつまみの日付と一致**することを確かめた（2019-04-15・2020-08-27・2021-12-18・2024-12-26 など）
- **ずれが出るのは「ブラウザのスクロールバーのつまみ」のほう**: 全体の高さは「測った行の実際の高さ ＋ 測っていない行は 92px」の合計なので、
  遠くへ飛ぶたびに少し伸び縮みする（スクロールバーのつまみの大きさ・位置が小さく動く）。日付のつまみは件数で並べているので動かない
- 行の高さを固定すれば、全体の高さが最初から決まり、スクロールバーも動かなくなる。**固定するかどうかは利用者と相談する**

## 3. 絞り込み中・検索中（いまの割り切り）

画面側の絞り込み（`mailFilters.ts` のトグル・期間・タグ・反転）は、**読み込んだ行に対して手元でかけている**。
DB の件数と画面の行がずれるので、絞り込み中は**つまみを出さず、いままでどおり上から順に読み足す**
（先頭から途切れずに読んだ部分だけを絞り込んで見せる。`loadMore`・`AUTO_FILL_CAP`）。検索（FTS・最大 200 件）も同じくつまみを出さない。

### 3.1 次の段: 絞り込みを DB 側へ寄せる

つまみを絞り込み中にも出すには、絞り込みを `thread_list` / `thread_day_counts` の **WHERE に入れる**のが筋。

| 絞り込み | DB 側で書けるか |
|---|---|
| 未読・スター・ブックマーク・添付 | 列がある（スター・ブックマークはスレッド集約なので、`thread_list` と同じ副問い合わせが要る） |
| 期間 | `date_ts` の範囲（端末ローカルの日付境界を秒に直して渡す） |
| タグ | `email_tags` の EXISTS |
| 知り合い・VIP・返信歴 | `known_vip_cols` / `replied_col` と同じ式を WHERE に |
| グリーン | 認定ドメインの集合と照らす（いまは Rust で後付けしている）。SQL へ寄せるか、集合を一時表にする |
| 反転 | 上の条件の否定を組み立てる |

- 両方の問い合わせで**同じ関数**から WHERE を組む（Photosky の `build_list_filter` と同じ）。そうしないと累計と OFFSET がずれる
- 検索は FTS の一致をスレッドへ束ねてから同じく数えれば出せる（いまは 200 件で打ち切っている）

## 4. 割り切り・既知の課題

- **夏時間の切り替えが深夜 0 時にある地域**（チリなど）では、`date_ts` の順と「ローカルの日付」の順が 1 時間だけ逆転し、
  同じ日の区間が 2 つに分かれる可能性がある（そのときは累計と OFFSET が局所的にずれる）。日本・米国・欧州の切り替え時刻では起きない
- 絞り込みのオン・オフでは、スクロール量（px）がそのまま残る（従来と同じ）。絞り込みを外すと、近いけれど同じではない位置に出る
- 行の高さの合計がブラウザの要素の高さの上限（Chromium で約 3,300 万 px）を超えると描けない。1 行 約 90px なら約 36 万スレッドまで

  - 印が一番上の行の位置に出る
  - 開く・矢印キーで次へ（開いた行に寄せる）・Ctrl で複数選択・Delete でゴミ箱（行が詰まる）・Ctrl+Z で元に戻す（位置はそのまま）

  - フォルダ切り替え（送信済み → 受信箱）・アカウント切り替え（「全て」で 5,504 件）・切り替え後に古い日付へ飛ぶ
  - 新着（DB に 3 通足して読み直し）が先頭に入る
  - 未読の絞り込み・検索ではつまみが出ない
- **確かめていないこと**:
  - 引っ張る（押したまま動かす）・ホイールでのスクロール（`swaymsg` の押したままの移動とホイールは WebView に届かない。会話と同じ道具の制約）

  - Windows（`zv` / `vaio`）
