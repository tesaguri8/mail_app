## 1. リモート画像/外部コンテンツの既定ブロック

HTMLメールの外部画像は**開封トラッキング（追跡ピクセル）**になり得る。

- **既定でブロック**: 外部画像・CSS・フォント等を読み込まない。プレースホルダ＋「画像を表示」ボタンを表示。
- **許可の粒度**: この差出人は常に許可 / この1通だけ許可 / 全許可（非推奨）。許可は `contacts.allow_remote_images` 等で保持。
- **追跡ピクセル検出**: 1x1・既知トラッカードメイン等を検出して可視化（「このメールに追跡画像 N 個」）。
- **インライン画像（cid:）はブロック対象外**（添付に含まれるため追跡にならない）。

> 看板「AIにもトラッカーにも勝手に渡さない」に直結。実装も比較的軽い。**最初の差別化として優先**。

### 1.1 「表示するだけ」のリスクと、サニタイズ・プロキシ（任意・将来）

外部画像を**表示する（読み込む）行為そのもの**が、クリック不要でサーバへ HTTP リクエストを飛ばす＝**開封トラッキング**になる。これが既定ブロックの主目的。加えて「表示するだけ」で成立しうる攻撃が 1 つある：

- **画像デコーダの脆弱性**（ゼロクリック）: 細工画像を**表示するだけ**で任意コード実行に至った実例がある（WebP `CVE-2023-4863`、Apple `FORCEDENTRY`/`CVE-2021-30860` 等）。Tauri のデコードは OS の WebView 依存のため、**WebView が最新なら実務上は概ね防げる**が、ゼロではない。
- 逆に**ステガノグラフィ・EXIF・ポリグロット**は「見る側」への攻撃ではない（`<img>` として解釈される限りコードは走らない）。**SVG のみ例外**（`<script>` を持てる）だが、本文レンダラは `svg` を DROP 済み＋`innerHTML` 不使用のため実行されない（[HtmlText.tsx](../src/renderer/components/HtmlText.tsx)）。

これらを踏まえ、外部画像は **TSG One（TSG Core）の画像プロキシ**経由で取得する選択肢を用意する。単なる中継ではなく**再エンコード型サニタイズ層**として設計し、一挙に複数の効能を得る：

1. **IP を隠す**（受信者の居場所・回線が送信者に渡らない）
2. **開封トラッキングを無効化**（送信者から見て誰がいつ開いたか分からない）
3. **デコーダ攻撃を無害化**: サーバ側で一度デコードし、クリーンな PNG/JPEG に**焼き直して**配信するため、悪意あるバイト列（上記 WebP/FORCEDENTRY 系）が壊れて無力化される
4. **EXIF/メタデータ除去**（副次的なプライバシー向上）

> Gmail の画像プロキシ（`googleusercontent.com` 経由）と同じ設計思想。「表示するだけなら安全」を**本当に安全**へ引き上げつつ、ブロック解除の一手間なく最初から画像が見える UX を実現できる。**サーバー依存**になるためオプション（ローカル完結を望むユーザーは従来どおり手動許可）。プロキシ側の設計は TSG Core `docs/IMAGE_PROXY_PLAN.md` を参照。

## 2. なりすまし/フィッシング警告

差出人の正当性と危険サインを**画面で分かりやすく**示す。

### 認証結果（[THREADING.md](THREADING.md) §7.5 の `Authentication-Results` を活用）
- **SPF / DKIM / DMARC** の pass/fail をバッジ表示。fail や不一致は警告色。
- `From` と `Return-Path`/`Reply-To` の不一致を提示。

### なりすまし検知
- **表示名スプーフィング**: 既知の表示名なのに**アドレスが普段と違う**（連絡先と照合）→ 警告。
- **類似ドメイン（ホモグラフ）**: punycode/紛らわしい綴り（`rn`↔`m` 等）を検出。
- **初回の差出人**: 「初めての相手」インジケータ。

### 危険リンク/添付
- **リンク偽装**: 表示テキストと実 URL（href）の不一致、punycode、既知の悪性ドメインを警告。クリック前に実リンクをプレビュー。
- **危険な添付**: 実行ファイル・二重拡張子（`.pdf.exe`）・マクロ文書を警告。暗号化アーカイブは「中身を検査できない」注記。

> 素材は標準ヘッダ＋連絡先照合。**表示設計（バッジ・警告の見せ方）**を本書で定義し、過剰警告にならない粒度にする。

## 3. データモデル（要約）

- `contacts.allow_remote_images`（差出人ごとの画像許可）
- `emails.auth_result`（既存。SPF/DKIM/DMARC サマリ）を表示に利用
- ブロック状態・追跡検出数は表示時に算出（必要なら `emails` にキャッシュ列）

## 4. Tauri コマンド（抜粋）

| コマンド | 用途 |
|---|---|
| `mail_render_safe` | リモート画像を抑止して本文をレンダリング |
| `mail_load_remote` | 明示的に外部画像を読み込む（この1通/この差出人） |
| `sender_set_remote_policy` | 差出人ごとの画像許可を設定 |
| `mail_security_report` | 認証結果・なりすまし/危険サインの一覧を返す |

## 5. 実装フェーズ（ロードマップ）

画像安全まわりの実装順。**受信側（本書）＋送信側（[COMPOSE.md](COMPOSE.md) §3）＋サーバ側（TSG Core）**を通した計画。現状：`contacts.allow_remote_images` は**DBカラム・モデルとも実装済み**（`migrations/0016_contacts.sql`）だが、リモート取得の実装・コマンドは**未着手**（`reqwest` 無し）。今は常時ブロックでプレースホルダ 🖼 のみ。画像 decode/re-encode 基盤は `services/media.rs` に既存（再エンコード時点で EXIF も落ちる）。

### Phase 0 — プレースホルダ誤ナビ修正（最優先・極小）
`<a>` の子である 🖼 `<span>` のクリックが親アンカーへバブリングし、リモート画像プレースホルダを押すとリンク先へ飛んでしまう。`renderer/components/HtmlText.tsx` のプレースホルダ span に `onClick` で `preventDefault()`＋`stopPropagation()` を付けて伝播を止める。規模: **S**（数行）。フィッシング誤タップを即座に潰せる。

### Phase 1 — 受信側「画像を表示」UX ＋ リモート画像取得
既定ブロックは維持しつつ明示許可で表示可能に。看板機能。
- Cargo に `reqwest`（既存 `native-tls` を再利用）を追加。
- `mail_load_remote(urls)`：http(s) のみ・サイズ/タイムアウト上限。取得後 `media.rs` で再エンコード（＝デコーダ攻撃・EXIF も無害化。§1.1）→ data URL 化。
- `sender_set_remote_policy`：`contacts.allow_remote_images` を更新（基盤は既存）。
- `HtmlText.tsx`：`inlineImages` と同型の `remoteImages` を受け取り実 `<img>` を描画＋remote 画像件数を集計。
- `MailBody.tsx`：本文上部にバナー「外部画像 N 個 ［画像を表示］［この差出人を常に許可］」。許可済み差出人は自動ロード。
- （任意）追跡ピクセル検出（1x1・既知トラッカー）を可視化。
- 規模: **L**。`mail_render_safe` / `mail_security_report`（§4）もこのフェーズに置く。

### Phase 2 — 送信側 EXIF/メタデータ削除
→ 詳細は [COMPOSE.md](COMPOSE.md) §3。受信側と独立で **Phase 1 と並行可**。規模: **M**。

### Phase 3 — TSG Core サニタイズ・プロキシ（任意・将来／サーバ側）
§1.1 のプロキシを実装。HMAC 署名 URL・SSRF ガード・再エンコード。Rondine 側は `mail_load_remote` に `via_proxy` を足すだけ（Phase 1 の拡張）。設計は TSG Core `docs/IMAGE_PROXY_PLAN.md`。コア安定後で良い。規模: **L（別リポ）**。

> **推奨順序: Phase 0 → 1 → 2**（0 は即修正、1 が看板、2 は独立で並行）。3 はサーバ都合で後回し。
