# 組織の連絡先（組織カードを連絡先に統合する）

**ステータス:** 実装済み（2026-10-12・ブランチ `feat/org-as-contact`）。§9 の要判断 A〜J はすべて推し（①）で進めた
（利用者の了承 2026-10-11、担当経由）。実装で設計から変えた点・決めた点は §10、確かめたことは §11。
前提: dev 23511b9（組織欄の色分け `feat/org-field-status` を含む）。

関連: [CONTACT_MODEL.md](CONTACT_MODEL.md)（§4・§4-1 をこの文書で置き換える）/ [CONTACTS_SYNC.md](CONTACTS_SYNC.md)

## 0. 要望と方針

**利用者の要望:** 一覧にある会社名だけの連絡先（例「sngDESIGN名護」）は、組織として連絡先に登録される形にしたい。
組織の情報は連絡先の画面でしか編集しない。

| 方針 | 中身 |
|---|---|
| 組織も連絡先の 1 件 | `contacts` に種別（人／組織）を持たせる。一覧では人と並べ、ビルのアイコンで見分ける |
| 代表の情報は子テーブル | 代表電話・FAX・代表メール・URL・所在地は、**いまある**連絡先の子テーブル（`contact_phones` / `contact_emails` / `contact_urls` / `contact_addresses`）に持つ。`organizations` の列は移して表ごと消す（二重に持たない。リリース前なので継ぎ足さない） |
| 組織タブは「見る・つなぐ」 | 代表の情報とメンバーを表示し、［連絡先で編集］で連絡先の画面へ移る。**組織タブに編集の画面を持たない** |
| 人 → 組織のつながり | `contact_organizations.org_id` は**組織の連絡先**（`contacts.id`）を指す |
| Google にも送る | 名前が空で `organizations[0].name` だけの Person として送る。Google から来たものは同期を続ける。新しく作る組織は、人と同じ「同期先」のチェックで決める |
| その場で切り替える | 会社名だけの連絡先は、消して作り直さずに**その場で**組織の連絡先にする（Google のつながり・`uid`・別人の記録・メールとの関係を保つ） |
| 既存の組織カード | それぞれ組織の連絡先にする。同じ名前の会社名だけの連絡先があれば、それと 1 つにまとめる |

## 1. 表の形

### 1-1. `contacts.kind`

```sql
ALTER TABLE contacts ADD COLUMN kind TEXT NOT NULL DEFAULT 'person'
    CHECK (kind IN ('person', 'organization'));
CREATE INDEX idx_contacts_kind ON contacts(kind) WHERE kind = 'organization';
```

- 境界型は `ContactKind`（`Person` / `Organization`。ts-rs で `'person' | 'organization'`）。
  `ContactSummary` / `ContactListItem` / `ContactInput` に `kind` を足す
- 組織の連絡先では、人の項目（姓名・よみの姓名・敬称・ニックネーム・旧姓・誕生日・記念日・関係）は使わない（NULL・空）。
  編集画面で出さない。取り込みで来ても捨てずに持つ（§3-2）

### 1-2. 組織の名前は「自分の会社の行」に持つ

組織の連絡先の名前とよみは、**その連絡先の `contact_organizations` の `position = 0` の行**（`name` / `phonetic_name`。
`org_id = NULL`・役職と部署は空）に持つ。`display_name` はそこから保存時に組み立て、`sort_name` はよみ、無ければ名前。

- **Google の Person の形とそのまま重なる**（名前が空で `organizations[0].name`）。取り込み・送信の変換に特別な分岐が要らない
- **会社名だけの連絡先は、もうこの形をしている**（姓名が空で会社の行が 1 つ）。その場の切り替えは `kind` を変えるだけで済む
- vCard でも `N` が空・`ORG` に名前・`X-ABShowAs:COMPANY` の形がそのまま重なる

### 1-3. 代表の情報（`organizations` の列の移し先）

| `organizations` の列 | 移し先 | ラベル |
|---|---|---|
| `name` / `name_kana` | 自分の会社の行の `name` / `phonetic_name`（§1-2） | — |
| `phone` | `contact_phones` | `代表` |
| `fax` | `contact_phones` | `FAX` |
| `email` | `contact_emails` | `職場`（**要判断 J**） |
| `url` | `contact_urls` | `ホームページ` |
| `postal`〜`country` | `contact_addresses` | `職場` |
| `note` | `contacts.note` | — |
| `deleted_at` / `created_at` / `updated_at` | `contacts` の同じ列 | — |

- 組織の連絡先の電話・メールは複数持てる（いまの組織カードは 1 つずつだった）
- 人の連絡先の `is_shared`（会社の代表番号・共有アドレスの印）は、いままでどおり人の側に残す

### 1-4. `contact_organizations.org_id` の付け替え

SQLite は外部キーを後から変えられないので、`contact_organizations` を作り直す。

```sql
-- org_id は組織の連絡先（contacts.id。kind = 'organization'）を指す。
org_id INTEGER REFERENCES contacts(id) ON DELETE SET NULL
```

- 「指す先が組織であること」は書き込み層（`contact_write::resolve_orgs`）で守る（SQLite の CHECK は他の表を見られない）
- 組織の連絡先の自分の会社の行は `org_id = NULL`（自分を指さない）

### 1-5. 消すもの

- 表 `organizations`（0026・0027・0052 で足した列ごと）
- **`contacts.show_as_company`**: `kind` と意味が重なる（要判断 A）

## 2. マイグレーション

番号は **0066**（2026-10-11 に全リモートブランチを確かめた。最大は 0065 で、0066 以降を持つブランチは無い）。

### 2-1. 0066（SQL）

1. `contacts.kind` を足す
2. 組織カード 1 枚ごとに組織の連絡先を作る（ゴミ箱のカードは `deleted_at` を引き継いでゴミ箱へ）。
   新旧の id の対応は、作業用の列 `contacts.legacy_org_id` に控える（最後に `ALTER TABLE … DROP COLUMN` で消す）。
   `uid` はトリガーが振る
3. §1-3 の表のとおり、代表の情報を子テーブルへ写す。自分の会社の行（§1-2）を足す
4. `contact_organizations` を作り直し、`org_id` を新しい id へ付け替える
5. `show_as_company` を `kind` へ写して列を消す（要判断 A の答えによる）
6. `organizations` を消す

**同期の印は戻さない**（入れ直しはしない。0059 とは違う）。

### 2-2. 起動時に 1 回だけ: 同じ名前の会社名だけの連絡先とまとめる（Rust）

正規化（`dedupe::normalize_org`。「(株)」と「株式会社」の違いなど）は SQL では書けないので、
`bodyrepair.rs` と同じく、起動時に 1 回だけ走る処理にする（`app_settings` の `org_contacts.merged_version`）。

- 対象: 0066 で組織カードから作った組織の連絡先（どこにもつながっていない）と、
  **正規化した名前が同じ「会社名だけの連絡先」**（§4-1 の判定）
- **残すのは会社名だけの連絡先の側**（Google のつながり・`uid`・別人の記録・メールとの関係を持っているため）。
  `kind = 'organization'` にし、組織カードの代表の情報のうち無い値を足し、メモは後ろにつなぐ。
  人からのつながり（`org_id`）を付け替えて、カードから作った側を消す
- 同じ名前の会社名だけの連絡先が 2 件以上あれば、つながりの多い方（同点なら古い方）を残し、
  残りは重複の整理（組織）の候補に出す（自動ではまとめない）
- Google につながっている側へ値を足したときは、送り直しの印を立てる（要判断 C）
- 試験: 0066 の前後で、人から組織へのつながり・代表の情報・ゴミ箱・`uid` が保たれること

## 3. Google との写し方

### 3-1. 送る（`outgoing.rs`）

| 項目 | 人 | 組織 |
|---|---|---|
| `names` | 姓名（姓名が無ければ表示名を姓に入れる＝今のまま） | **空にする**（表示名を姓に入れない。会社名だけの連絡先で起きていた「会社名が姓にも付く」を止める） |
| `organizations` | 会社の行 | 自分の会社の行（名前・よみ。役職・部署は空） |
| 電話・メール・URL・住所・メモ | 今のまま | 今のまま（代表電話・FAX・代表メールも普通の値として送る） |

- 送る直前に読み直した Person を土台にする規則（CONTACT_MODEL.md §3）はそのまま。
  Google 側に以前送った「会社名と同じ姓」が残っている連絡先は、`names` を空で送ると消える（要確認: §8）
- **CONTACT_MODEL.md §4 の「組織カードの代表電話…はどのサービスにも送らない」は取り消す**（組織の情報は組織の連絡先の値として送る）
- 人の会社の行は、つながった組織の名前にそろえて送る（今の `sync_member_names` のまま）

### 3-2. 取り込む（`incoming.rs`）

- Google の Person には種別が無い。**種別は Rondine だけが持ち、取り込みでは変えない**（組織の連絡先は組織のまま、人は人のまま）
- 組織の連絡先の表示名は、自分の会社の行の名前から組み立てる。Google で姓名が足されても表示名は組織名のまま（姓名は捨てずに持つ）
- 名前が空で会社だけの Person が**新しく**来たときは、人として作り、整理の候補（§4-1）に出す（要判断 B。自動で組織にする案もある）
- 人の会社名から組織へつなぐ規則は今のまま（正規化名が一致する組織の連絡先があればつなぐ。作らない）

### 3-3. 新しく作るとき

| 経路 | 同期先 |
|---|---|
| 連絡先の画面で「新しい組織」 | 人と同じ「同期先」のチェック（最初から入っていて、前回の選択を覚える） |
| 人の会社欄に新しい名前を入れて保存（今「カードを作る」経路） | **要判断 D** |
| 整理の「組織の連絡先にする」・「組織に登録」 | **要判断 D**（上と同じ扱いにする） |
| 会社名だけの連絡先の切り替え | つながりはそのまま（Google にあれば Google のまま） |

### 3-4. iCloud（vCard）

- 書き出し: 組織の連絡先は `N` を空、`ORG` に名前、`X-ABShowAs:COMPANY` を付ける
- 取り込み: `X-ABShowAs:COMPANY` で姓名が空のカードは組織の連絡先として作る（ファイルは人が選んで入れるので、印を信じる）

## 4. 画面

### 4-1. 会社名だけの連絡先の判定と切り替え（整理）

**候補にする条件**（どちらか）:

- 姓・ミドル・名が空で、表示名が自分の会社の行の名前と（正規化して）一致する
- `show_as_company` が付いている（0066 で列を消すなら、0066 の時点で候補の印に写す — 要判断 A）

**整理の画面**（組織タブの「整理」に 1 つ足す）: 候補を一覧にし、チェックしてまとめて「組織の連絡先に切り替える」。

- 切り替えは `kind` を変えるだけ（§1-2）。Google のつながり・`uid`・別人の記録・メールとの関係はそのまま
- **切り替えた組織と同じ正規化名の会社を持つ人**を、その場で組織へつなぐか訊く（今の「組織カードにする」と同じく、再送になる人数を出す）
- 役職や部署の入った会社の行・メンバーのいる組織と同じ名前の候補は、切り替え前に理由を添える（取り違え防止）

### 4-2. 連絡先の画面

- **一覧**: 組織はビルのアイコン（頭文字の代わり）。2 行目は会社名の繰り返しをやめ、代表電話か代表メール（無ければメンバー数）
- **絞り込み**: 「すべて / 人 / 組織」を足すか（要判断 E）
- **新規作成**: 「新しい連絡先」の隣に「新しい組織」（または作成画面の先頭で人／組織を選ぶ）
- **組織の詳細・編集**: 名前・よみ・電話（代表・FAX）・メール・URL・住所・メモ・タグ・同期先。人の項目は出さない。
  下に**メンバー**（読み取り専用の一覧。クリックでその人へ）。「会社として表示」のトグルは「組織」の切り替えに置き換える
- **人の詳細**: 会社欄の下の組織の情報（今の `OrgCardInfo`）は残し、［編集］は組織の連絡先へ移る（`OrgCardDialog` は消す）
- **「組織に登録されています。統合しますか？」**（`OrgOverlapNotice` / `utils/orgOverlap.ts`）は残す。比べる相手を、組織の連絡先の電話・メール・住所にする
- **会社欄**（`OrgCombobox` / `OrgRegister`）: 候補は組織の連絡先。色分け（つながっていない＝赤・似た組織あり＝黄、`feat/org-field-status`）は
  意味を変えずに残す（「組織カード」の言葉を「組織」に直す）
- **重複の整理（人）から組織を外す**: 組織の代表番号・代表メールは、メンバーの共有の値と同じことが多く、人と組織が重複の組になってしまう。
  人と組織は比べない。組織どうしは今の「組織」モード（正規化名）で比べる

### 4-3. 組織タブ（見る・つなぐ）

| いまの機能 | 移し先 |
|---|---|
| 一覧・検索 | 組織の連絡先の一覧（`kind = 'organization'`）。検索は名前・よみ |
| カードの編集（名前・代表の情報・メモ） | **消す**。［連絡先で編集］で連絡先タブのその組織を開く |
| メンバーの一覧・共有アドレスの集計 | 残す（読み取り専用） |
| 削除・ゴミ箱・復元 | 連絡先のゴミ箱に一本化する（組織タブからは消さない。要判断 F） |
| 名前を変えると「統合」の確認 | 消す（名前は連絡先の画面で変える。重複は整理へ） |
| 整理: カードになっていない会社名 →「組織カードにする」 | 「組織の連絡先にする」（同期先は要判断 D） |
| 整理: つながっていない人 →「つなぐ」 | そのまま（つなぐ先が組織の連絡先になるだけ） |
| 整理: 組織の重複（`OrgDuplicates`） | 統合を**連絡先の統合**（`contact_dedupe` の merge）で行う。つながり・`uid`・別人の記録を寄せ、人からの `org_id` を残す側へ付け替える |
| **（新）** 整理: 会社名だけの連絡先 → 切り替え | §4-1 |

### 4-4. 文言

「組織カード」は「組織」に揃える（`org.*` / `contact.orgStatusNoCard` など）。ja / en とも。

## 6. ほかの機能への影響

| 機能 | 変わること |
|---|---|
| 差出人名の解決・知り合い/グリーン判定 | 組織の代表メールが連絡先のメールになるので、**代表メールから届いたメールは「知り合い」になり、差出人名が組織名で出る**（今は組織カードのメールは見ていない。要判断 G） |
| 宛先の候補 | 組織の代表メールが候補に出る（会社名は組織名） |
| 迷惑判定の「連絡先にある」 | 上と同じく組織の代表メールが入る |
| 連絡先の件数（フッター） | 組織も数える（要判断 E と合わせる） |
| 書き出し（vCard / Google CSV） | 組織も 1 件として出す（§3-4） |
| ゴミ箱の期限切れ消去 | `organizations` の消去をやめる（連絡先の消去に含まれる） |
| 予定の参加者 | 変わらない |

## 7. 進め方（実装の段）

1. **0066 と起動時のまとめ**（§2）・store 層（`kind`・`resolve_orgs` の付け替え・`organizations.rs` / `org_tidy` の読み先）。Rust の試験
2. **Google と vCard の写し方**（§3）。送信の本文の試験（組織は `names` を空に）
3. **画面**: 連絡先（一覧のアイコン・組織の編集・メンバー）、組織タブ（読み取り専用＋［連絡先で編集］）、整理（切り替え候補）
4. raytrek の作り物の DB で、組織カード 16 枚＋同じ名前の会社名だけの連絡先で 0066 を通し、GUI で確かめる（Google へは送らない）
5. vaio の実データで確かめる（担当／利用者）。とくに Google に `names` を空で送ったときの見え方（§8）

## 9. 要判断

| | 問い | 案（先頭が推し） |
|---|---|---|
| **A** | `show_as_company` を消して `kind` に一本化するか | ① 消す。0066 で「`show_as_company = 1` かつ姓名が空」の人は組織に切り替え、姓名のある人は印を落とす／② 列は残し、vCard の往復と候補の印にだけ使う |
| **B** | Google から新しく来た「名前が空で会社だけ」の Person を自動で組織にするか | ① しない。人として作って整理の候補に出す（判定は人が決める・既存と同じ規則）／② 自動で組織にする |
| **C** | §2-2 でまとめたとき、Google につながっている側へ組織カードの代表の情報を足したら、送り直すか | ① 送る（Google 側にも代表電話などが入る。方針「組織も Google へ送る」に沿う）／② 送らない（その人を次に編集したときに送る） |
| **D** | 人の会社欄・整理・「組織に登録」から**暗黙に**組織を作るときの同期先 | ① Rondine だけ（あとで組織の連絡先の同期先で選ぶ。勝手に Google が増えない）／② 新規作成の同期先の既定（前回の選択）に従う |
| **E** | 連絡先の一覧に「すべて / 人 / 組織」の絞り込みを足すか。件数に組織を含めるか | ① 足す。件数は絞り込みに従う／② 足さない |
| **F** | メンバーのいる組織を消せるか | ① 消せる（ゴミ箱へ。つながりは残し、完全に消えたら人の会社名は文字だけ残る）／② 今どおり、メンバーがいたら消せない |
| **G** | 組織の代表メールから届いたメールを「知り合い」として扱ってよいか | ① 扱う（組織を登録した＝付き合いがある）／② 扱わない（組織のメールは判定から外す） |
| **H** | 0066 で組織カードから作った組織の連絡先（どこにもつながっていない）の同期先 | ① Rondine だけ（利用者が組織ごとに選ぶ）／② Google の連携があれば Google へ作る |
| **I** | 人と組織の切り替えを、整理だけでなく連絡先の編集画面でも許すか | ① 許す（「会社として表示」のトグルの置き換え）／② 整理の画面だけ |
| **J** | 代表メールのラベル | ① `職場`／② 無ラベル |

## 10. 実装メモ（設計から変えた点・決めた点）

- **`OrganizationSummary` は消さずに、組織の連絡先から組み立てる読み取り専用の形として残した**（§5 では消す予定だった）。
  組織タブ・人の詳細の組織の情報・会社欄の候補・「統合しますか？」が 1 つずつの代表値（代表電話＝FAX 以外の先頭の電話、
  FAX＝ラベル `FAX` の先頭、代表メール・URL・所在地＝先頭）で組み立てられているため。`OrganizationInput` と
  `organization_upsert` / `delete` / `restore` は消した（編集・ゴミ箱は連絡先と同じ）
- **起動時のまとめ（§2-2）では、名前は組織カードの名前を残す**。カードにつながっていた人の会社名はもうカードの名前なので、
  その人たちを送り直さずに済む（会社名だけの連絡先の名前を残すと、メンバー全員の会社名が変わり、全員が送り直しになる）。
  残す側（会社名だけの連絡先）は名前が変われば送り直しの印が立つ
- **会社名だけの連絡先の判定を広げた**: 姓が空のほか、**姓が会社名と同じ**ものも候補にする。以前の送信で表示名を姓に
  入れていた（`outgoing::names`）ため、Google から会社名が姓として戻ってきている連絡先がある
- **書き込みの規則**（`contact_write::write_contact`）: 組織の先頭の会社（自分の会社の行）はどこにもつながない。
  表示名は自分の会社の行の名前、並び順はそのよみ。組織を書くたびにメンバーの会社名をそろえる（変わった人だけ送り直す）。
  人に戻した連絡先を指していた `org_id` は外す（会社名は文字として残る）。`org_id` に人や自分自身を渡されてもつながない
- **会社欄・整理から暗黙に作る組織は Rondine だけ**（要判断 D）。同期先は組織の連絡先の画面で選ぶ
- **重複の整理**: 人の重複の整理（1 件ずつ・まとめて）から組織を外した（`load_all_people`）。Google の取り込みの照合
  （`contacts_for_dedupe`）は組織も含めたまま（会社だけの Person が組織の連絡先に当たるように）。組織の統合は
  連絡先の統合（`merge_in`）で行い、`merge_in` は消える側を指していた人の `org_id` を残す側へ付け替える
- **整理の画面**: 4 つ目「会社名だけ」を足した（`OrgTidyCompanyOnly.tsx`）。役職・部署のある候補は最初はチェックを外す。
  整理の切替が左の枠に収まらないので、戻る・取り直しとは別の段に置いた（重複整理の切替も同じ）
- **一覧**: 「すべて / 人 / 組織」の絞り込み（件数のフッターも絞り込みに従う）と「組織を追加」。組織の 2 行目は代表メール
- 「組織に登録」・会社欄の色分け（赤・黄）は意味を変えずに残し、文言の「組織カード」を「組織」に直した
